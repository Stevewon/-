# QuantaEX — KR/JP 실전 리허설 체크리스트 (Go-Live Rehearsal)

> 대상: quantaex.io 프로덕션 · **반드시 한국(KR) 또는 일본(JP) 네트워크에서 수행**
> (미국은 지역차단 451, 그 외 CN/RU/IR/KP/CU/SY/BY 차단)
> 목적: 실제 유저를 받기 전에 **가입→인증→KYC→입금→거래→출금** 전 구간을 손으로 1사이클 돌려 검증.

---

## 0. 현재 프로덕션 상태 (2026-08-18 확인값 — 시작 전 재확인)

- 체인 드라이버: **`real` / integration_status: `live`** — mock 아님.
- 출금 방식: **수동 출금 모드**(`manual_withdrawal_mode: true`). 서버는 절대 서명하지 않고, **운영자가 퀀타리움 지갑 앱에서 직접 지급**한 뒤 tx_hash를 관리자 화면에 기록.
- 입금: **온체인 자동 크레딧**(크론 워커가 확인수 충족 시 지갑에 반영).
- 거래·출금: **KYC 'approved' 필수** (이메일 인증만으론 불가).
- **QX 웰컴보너스 100은 이메일 인증 후 지급** (가입만으론 0). 이 QX는 회사지급분이라 **외부 출금 불가, 내부 거래만 가능**.
- QTA/QX/QKEY 출금은 **퀀타리움 네트워크 주소로만** 가능(다른 체인 주소 입력 자체가 막힘).

시작 전 재확인 (브라우저 주소창):
```
https://quantaex.io/api/chain/qta/env-check-temporary
```
→ `"integration_status":"live"`, `"manual_withdrawal_mode":true` 인지 눈으로 확인. ☐

준비물:
- 테스트용 이메일 2개 (유저A, 유저B — B는 추천/화이트리스트/2차 시나리오용) ☐
- 소액의 실제 QTA (온체인 입금 리허설용) 또는 관리자 크레딧으로 대체 ☐
- 관리자 계정 (KYC 승인·출금 승인용) ☐
- 스마트폰(OTP 이메일 수신, 2FA 앱) ☐

## 1. 지역/접속 (Geo) — 5분

- ☐ KR/JP IP로 `https://quantaex.io` 접속 → 정상 로딩(451 아님).
- ☐ (가능하면) VPN으로 US 접속 → **451 GEO_BLOCKED** 확인(차단 정상 동작).
- ☐ 모바일 브라우저에서도 첫 화면·로그인 진입 정상.

---

## 2. 회원가입 & 이메일 인증 — 10분

- ☐ 우측 상단 **English가 기본 언어**인지 확인. 언어 선택기에 **한국어(Korean) 항목이 없어야** 함(정상).
- ☐ 가입 폼: 이메일/비번/비번확인 입력.
- ☐ **국가 선택**: 필드 탭 → **아래에서 올라오는 바텀시트**가 뜨고 배경 불투명(뒤 텍스트 안 비침), 검색으로 "Korea"/"Japan" 찾아 선택. ☐
- ☐ 추천코드(있으면) 입력 → **"유효한 코드"** 표시되고 **코드 주인 아이디/닉네임은 절대 안 보임**. ☐
- ☐ 가입 완료 → 이 시점 지갑 확인: **QX 잔액 0** (가입만으론 보너스 미지급). ☐
- ☐ 인증 이메일 수신 → 링크/코드로 **이메일 인증 완료**.
- ☐ 인증 직후 지갑 재확인: **QX 100 지급됨**, 단 "출금가능(withdrawable)"이 아니라 **회사지급분**으로 표시(외부 출금 불가). ☐

---

## 3. 로그인 & 보안 (OTP/2FA) — 10분

- ☐ 로그아웃 후 재로그인 → **이메일 OTP 단계**가 뜨는지(step-up) → 코드 입력 후 로그인 성공. ☐
- ☐ 2FA 설정(설정 화면) → 인증앱 등록 → 로그아웃/재로그인 시 2FA 코드 요구되는지. ☐
- ☐ 잘못된 OTP/2FA 코드 → 거부되는지. ☐

---

## 4. KYC 제출 & 승인 — 10분

- ☐ KYC 미제출 상태에서 **주문/출금 시도 → 403 KYC_REQUIRED**로 막히는지(정상). ☐
- ☐ 유저A로 KYC 제출(이름/전화/신분증 등).
- ☐ 관리자로 `https://quantaex.io/admin` 로그인 → KYC 대기목록에 유저A 표시 → **승인**. ☐
- ☐ 유저A: KYC 상태 **approved**로 갱신 확인. 이제 거래/출금 버튼 활성화. ☐

---

## 5. 입금 (온체인 자동 크레딧) — 15분

> 실제 온체인 입금이 부담되면 5-B(관리자 크레딧)로 대체 가능.

**5-A. 실제 온체인 입금 (권장, 소액)**
- ☐ 지갑 → 입금(Deposit) → 코인·네트워크 선택 → **내 입금 주소** 표시 확인(사용자별 고유).
- ☐ 그 주소로 **소액 실제 입금** 전송.
- ☐ 확인수 충족까지 대기 → **자동으로 지갑 available에 반영**되는지(크론 워커). ☐
- ☐ 입금 내역(History)에 completed로 표시. ☐
- ☐ **이중 크레딧 없음** 확인: 잔액이 보낸 금액과 정확히 일치(2배 아님). ☐ *(A3 수정 검증)*

**5-B. 관리자 크레딧 대체 (온체인 생략 시)**
- ☐ 관리자 → 수동 크레딧으로 유저A에 소액 지급(출금 리허설용은 `withdrawable: true`로).
- ☐ 유저A 지갑에 정확히 반영. ☐

---

## 6. 현물 거래 — 15분

- ☐ 지정가 매수 주문 1건 → 체결/부분체결/미체결 상태 정확. ☐
- ☐ 주문 취소 → **잠긴 잔액이 정확히 환불**(원복). ☐
- ☐ 지정가 매도 주문 1건 → 정상.
- ☐ 수수료가 명세대로 차감. ☐
- ☐ **동시성 스모크(선택)**: 잔액이 딱 1건만 감당 가능한 상태에서 `scripts/concurrency-check.mjs` T1 실행 → **1건만 통과**, 잔액 마이너스 없음. ☐ *(A1 주문 검증)*

---

## 7. 출금 — 가장 중요, 25분

**7-A. QTA/QX/QKEY 퀀타리움 전용 경고 (신규 기능 검증)**
- ☐ 출금에서 **QTA(또는 QX/QKEY)** 선택 → **빨간 "Quantarium Network only" 경고 배너** 표시. ☐
- ☐ **동의 체크박스 체크 전에는 주소 입력란이 잠김**(비활성). ☐
- ☐ 이더리움/트론 등 **다른 체인 주소 입력 → "올바른 퀀타리움 주소 아님"으로 거부**. ☐
- ☐ 올바른 퀀타리움 주소(0x+40hex) 입력 → 통과, 확인 단계에서도 재경고 표시. ☐

**7-B. 회사지급분 출금 차단**
- ☐ **웰컴보너스 QX(회사지급분)만으로 출금 시도 → 차단**(WITHDRAWAL_BLOCKED_COMPANY_ISSUED). ☐
- ☐ 실제 입금분/withdrawable 잔액으로는 출금 신청 가능. ☐

**7-C. 화이트리스트·한도·2FA**
- ☐ **화이트리스트 미등록 주소 → 출금 거부**("Add it first"). ☐
- ☐ 주소 등록 후 **24h 쿨다운** 동작. ☐
- ☐ 2FA 켠 상태에서 **코드 없이 출금 불가**. ☐
- ☐ 일일/건당 USD 한도 초과 시 거부. ☐

**7-D. 출금 신청 → 관리자 수동 지급 → 완료**
- ☐ 유저A: 소액 출금 신청 → 지갑에서 해당 금액이 **available→locked로 이동**. ☐
- ☐ 관리자 화면: 출금 대기목록에 표시.
- ☐ 관리자 **승인** → 운영자가 퀀타리움 지갑 앱에서 **실제 지급** → **manual-complete**로 tx_hash 기록 → 상태 confirmed. ☐
- ☐ 유저A 지갑: locked에서 정확히 차감(available로 되돌아오지 않음). **이중 차감 없음**. ☐
- ☐ 유저에게 출금 완료 알림/메일 수신. ☐

**7-E. 출금 거부 → 환불 (버그 수정 검증)**
- ☐ 다른 출금 신청 1건 → 관리자 **거부** → **잠긴 금액이 available로 정확히 환불**. ☐ *(QTA 거부-환불 버그 수정 검증)*
- ☐ **동시성 스모크(선택)**: 같은 출금건에 관리자 승인/거부 동시 발사 `concurrency-check.mjs` T3 → **1번만 처리, 나머지 409**. ☐ *(A2 검증)*

## 10. 합격 기준 (Go / No-Go)

**GO 조건 (전부 충족):**
- 가입→인증→KYC→입금→거래→출금→(승인·거부) 1사이클 **자금 오차 0**.
- 이중 크레딧 / 초과 출금 / 이중 승인 **재현 안 됨**(동시성 T1·T2·T3 PASS).
- QTA/QX/QKEY 타 체인 주소 **입력 차단**, 회사지급분 **출금 차단** 동작.
- 지역차단(US 451) 정상, KR/JP 정상.

**NO-GO (하나라도 해당 시 개시 보류·엔지니어링 보고):**
- 잔액이 실제와 어긋남(이중 크레딧/차감, 마이너스).
- 동시 요청으로 1건 초과 통과.
- 다른 체인 주소로 QTA류 출금이 신청됨.
- 회사지급분이 외부로 출금 가능.

> 각 항목 옆 ☐ 에 체크하며 진행하고, 실패 항목은 캡처+요청ID(있으면)와 함께 기록해 주세요.
